# HTTPS to SOAP – Dynamic SOAP Integration

## Overview

This SAP Integration Suite (Cloud Integration / CPI) integration flow receives customer data as JSON over HTTPS, converts the JSON payload into XML, builds a SOAP 1.1 envelope using Groovy, and sends the SOAP XML to a mock endpoint hosted on Beeceptor.

The mock endpoint returns either a successful SOAP response or a SOAP Fault based on the customer ID.

> **Note:** This exercise uses an **HTTP Receiver Adapter** to send SOAP XML over HTTPS because no WSDL was available. It demonstrates SOAP message construction and HTTP-based SOAP communication; it does not use the SAP SOAP Receiver Adapter.

## Integration Flow

```text
External Client (Postman)
        |
        | HTTPS POST (JSON)
        v
HTTPS Sender Adapter
        |
        v
JSON to XML Converter
        |
        v
Groovy Script
(CreateSOAPEnvelope.groovy)
        |
        | Creates SOAP 1.1 Envelope
        v
Content Modifier
(SetDynamicSOAPHeaders)
        |
        | Content-Type: text/xml; charset=utf-8
        | SOAPAction: CreateCustomer
        v
HTTP Receiver Adapter
        |
        | HTTPS POST (SOAP XML)
        v
Beeceptor Mock Endpoint
        |
        +---- C1001 ----> HTTP 200 / SOAP Success
        |
        +---- C1002 ----> HTTP 500 / SOAP Fault
```

An Exception Subprocess is included in the iFlow to handle processing errors. In the current design it ends with an Error End Event, which propagates the exception; it should not be described as converting every receiver fault into a successful custom response.

## Components

### 1. HTTPS Sender Adapter

Receives incoming customer data from an external client using an HTTPS POST request.

Example sender resource path:

```text
/http/customer/soap
```

The actual URL is tenant-specific and is available from the deployed iFlow's endpoint details.

### 2. JSON to XML Converter

Converts the incoming JSON payload into XML so that the Groovy script can read the customer fields.

### 3. Groovy Script – CreateSOAPEnvelope.groovy

The script:

- Reads the converted XML payload.
- Extracts `CustomerID`, `CustomerName`, `City`, and `Mobile`.
- Escapes XML special characters in the extracted values.
- Builds a SOAP 1.1 Envelope containing a `CreateCustomerRequest`.
- Sets the message body as a Java `String`.

The SOAP namespace and operation in this exercise are illustrative:

```text
Namespace: urn:customer-service
Operation: CreateCustomerRequest
```

For a real SOAP service, use the namespace, operation, and XML structure specified by that service's WSDL.

### 4. Content Modifier – SetDynamicSOAPHeaders

Sets the HTTP message headers used when sending the SOAP XML:

| Header | Value |
|---|---|
| Content-Type | `text/xml; charset=utf-8` |
| SOAPAction | `CreateCustomer` |

The SOAPAction value must match the target service's contract in a real integration.

### 5. HTTP Receiver Adapter

Sends the SOAP XML payload to the Beeceptor endpoint using HTTP POST over HTTPS.

Example endpoint format:

```text
https://<your-beeceptor-subdomain>.free.beeceptor.com/customer
```

Use the actual endpoint generated in your Beeceptor account. Do not expose private credentials or tenant details in this README.

### 6. Exception Subprocess

An Exception Subprocess is present with a Content Modifier named `HandleSOAPFault` and an Error End Event. The Error End Event propagates the exception. If the requirement is to return a custom error payload without propagating the exception, the exception-handling design must be adjusted and tested separately.

## Input JSON

Send the following JSON to the deployed SAP CPI HTTPS sender endpoint:

```json
{
  "CustomerID": "C1001",
  "CustomerName": "Rahul Sharma",
  "City": "Hyderabad",
  "Mobile": "9876543210"
}
```

## SOAP Request Generated by CPI

The Groovy script creates a SOAP envelope similar to:

```xml
<soapenv:Envelope
    xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:cus="urn:customer-service">
    <soapenv:Header/>
    <soapenv:Body>
        <cus:CreateCustomerRequest>
            <cus:CustomerID>C1001</cus:CustomerID>
            <cus:CustomerName>Rahul Sharma</cus:CustomerName>
            <cus:City>Hyderabad</cus:City>
            <cus:Mobile>9876543210</cus:Mobile>
        </cus:CreateCustomerRequest>
    </soapenv:Body>
</soapenv:Envelope>
```

## Mock Service Scenarios

The Beeceptor mock endpoint is configured with two POST `/customer` rules:

| Customer ID | HTTP Status | Mock response |
|---|---:|---|
| `C1001` | 200 | SOAP success response |
| `C1002` | 500 | SOAP Fault response |

### Successful SOAP Response

```xml
<?xml version="1.0" encoding="UTF-8"?>
<soapenv:Envelope
    xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:cus="urn:customer-service">
    <soapenv:Header/>
    <soapenv:Body>
        <cus:CreateCustomerResponse>
            <cus:Status>SUCCESS</cus:Status>
            <cus:CustomerID>C1001</cus:CustomerID>
            <cus:Message>Customer created successfully</cus:Message>
        </cus:CreateCustomerResponse>
    </soapenv:Body>
</soapenv:Envelope>
```

### SOAP Fault Response

For `C1002`, Beeceptor is configured to return HTTP 500 with a SOAP Fault containing:

- Fault code: `soapenv:Server`
- Error code: `CUSTOMER_001`
- Error message: `Duplicate or invalid Customer ID`

These are mock responses only. No real customer record is created or stored.

## Testing with Postman

### Test the successful scenario

1. Create a POST request.
2. Use the deployed SAP CPI HTTPS sender endpoint.
3. Set the header:

   ```text
   Content-Type: application/json
   ```

4. Select **Body → raw → JSON**.
5. Send the input JSON with `CustomerID` set to `C1001`.
6. The expected response is the SOAP success XML returned by Beeceptor.

### Test the SOAP Fault scenario

Repeat the request with `CustomerID` set to `C1002`.

Beeceptor is configured to return HTTP 500 and a SOAP Fault. The exact response observed by the Postman caller depends on how the CPI HTTP receiver error and Exception Subprocess are handled.

## Deployment

1. Save the integration flow.
2. Deploy the iFlow.
3. Open **Monitor → Integrations and APIs → Manage Integration Content**.
4. Confirm that the iFlow status is **Started**.
5. Open the deployed iFlow's endpoint details and copy the HTTPS sender URL.
6. Use that URL in Postman for testing.
