# Shipment Status Routing -- SAP Cloud Integration (CPI)

A hands-on SAP Integration Suite -- Cloud Integration practice project.
This iFlow receives shipment XML over HTTPS, stores the original
shipment status, transforms the XML, and routes the message according to
its status.

## Overview

This project demonstrates three SAP CPI palette steps:

1.  **Content Modifier** -- extracts `ShipmentStatus` from the incoming
    XML and stores it in an exchange property.
2.  **Message Mapping** -- transforms the source `Shipment` XML into the
    target `ShipmentResponse` structure.
3.  **Router** -- selects a route using the stored shipment status.

### Routing logic

  Shipment status    Router branch
  ------------------ -----------------
  `SHIPPED`          `Shipped_Route`
  `PENDING`          `Pending_Route`
  Any other status   Default route

## iFlow Design

``` text
HTTPS Sender
     |
Content Modifier
     |
Message Mapping
     |
   Router
   /  |  \\
  /   |   \\
SHIPPED PENDING Default
  |     |      |
 End   End    End
```

The Content Modifier saves the original status before mapping. This
allows the Router to evaluate the original value even if Message Mapping
changes the XML structure.

## Source XML

``` xml
<?xml version="1.0" encoding="UTF-8"?>
<Shipment>
    <ShipmentID>SHP1001</ShipmentID>
    <OrderID>ORD501</OrderID>
    <CustomerName>Rahul Sharma</CustomerName>
    <ShipmentStatus>SHIPPED</ShipmentStatus>
    <TrackingNumber>TRK98765</TrackingNumber>
</Shipment>
```

## Target XML

``` xml
<?xml version="1.0" encoding="UTF-8"?>
<ShipmentResponse>
    <ShipmentNumber>SHP1001</ShipmentNumber>
    <OrderNumber>ORD501</OrderNumber>
    <Customer>Rahul Sharma</Customer>
    <Status>SHIPPED</Status>
    <TrackingID>TRK98765</TrackingID>
</ShipmentResponse>
```

## XSD Files

-   `Shipment_Source.xsd` -- defines the incoming `Shipment` structure.
-   `Shipment_Target.xsd` -- defines the outgoing `ShipmentResponse`
    structure.

Import these schemas as the source and target message types in Message
Mapping.

## Configuration

### 1. HTTPS Sender

  Parameter                     Value
  ----------------------------- ---------------------
  Adapter                       HTTPS
  Address                       `/shipment-status`
  Authorization                 User Role
  Required role in this setup   `ESBMessaging.send`

The complete endpoint URL is generated by your SAP CPI tenant after
deployment. Copy the deployed endpoint from your tenant.

### 2. Content Modifier

Create an exchange property:

  Parameter     Value
  ------------- ----------------------------
  Name          `ShipmentStatus`
  Data type     `java.lang.String`
  Source type   XPath
  XPath         `/Shipment/ShipmentStatus`

For the sample XML, the property value is `SHIPPED`.

### 3. Message Mapping

Connect the fields as follows:

  Source field       Target field
  ------------------ ------------------
  `ShipmentID`       `ShipmentNumber`
  `OrderID`          `OrderNumber`
  `CustomerName`     `Customer`
  `ShipmentStatus`   `Status`
  `TrackingNumber`   `TrackingID`

### 4. Router

Configure the Router to evaluate the exchange property:

  Route             Condition
  ----------------- ------------------------------------------
  `Shipped_Route`   `${property.ShipmentStatus} = 'SHIPPED'`
  `Pending_Route`   `${property.ShipmentStatus} = 'PENDING'`
  Default route     Used when neither condition matches

Use the expression format supported by your Router configuration and
configure exactly one default route.

## Testing with Postman

1.  Deploy the iFlow.
2.  Copy the deployed HTTPS endpoint URL from SAP CPI.
3.  Create a `POST` request in Postman.
4.  Set `Content-Type: application/xml`.
5.  Configure the authorization required by your tenant.
6.  Send the XML payload with different `ShipmentStatus` values.

### Test cases

  Test   ShipmentStatus   Expected branch
  ------ ---------------- -----------------
  1      `SHIPPED`        `Shipped_Route`
  2      `PENDING`        `Pending_Route`
  3      `CANCELLED`      Default route

For the pending test, use:

``` xml
<ShipmentStatus>PENDING</ShipmentStatus>
```

For the default-route test, use:

``` xml
<ShipmentStatus>CANCELLED</ShipmentStatus>
```

## Monitoring

1.  Open **Monitor** in SAP Integration Suite.
2.  Open **Message Processing**.
3.  Find the message by timestamp or MPL ID.
4.  Check the processing status.

A successful status confirms that processing completed without a
reported error. It does **not by itself identify which Router branch was
selected**. Use tracing or an explicit branch-identification mechanism
during testing if you need to verify the selected route. Disable tracing
after testing, especially if payloads may contain sensitive data.

## Important Notes

-   The current practice flow ends each Router branch with an End event.
-   An End event does not send the transformed XML to an external
    receiver.
-   A successful HTTPS request does not automatically mean the mapped
    XML is returned in the HTTP response.
-   To deliver data to another system, configure the appropriate
    receiver adapter and endpoint.
-   To return the transformed XML to the HTTP caller, configure the
    appropriate HTTP response behavior.
-   Do not commit credentials, tenant URLs, certificates, or other
    secrets to GitHub.
