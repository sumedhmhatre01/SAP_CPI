# WSDL Creation and Message Mapping (Complex Mapping)

## Overview

This SAP CPI assignment transforms employee information into a payroll
employee XML response using **Graphical Message Mapping**. An employee
request is received through a SOAP sender endpoint, transformed, and
returned to the SOAP caller.

**Mapping implementation:** Graphical Message Mapping; no Groovy script
is used.

## Technologies and components

-   SAP Integration Suite -- Cloud Integration
-   SOAP Sender Adapter
-   WSDL and XML Schema (XSD)
-   Message Mapping artifact
-   Graphical mapping functions: `Concatenate`, `MapWithDefault`, and
    `Add`
-   Postman for endpoint testing

## Integration flow

``` text
HR System / Postman
        |
    SOAP Request
        v
 SOAP Sender Adapter
        |
        v
  Message Mapping
        |
 Employee XML → PayrollEmployee XML
        |
        v
    SOAP Response
        |
        v
HR System / Postman
```

The iFlow uses a synchronous SOAP request-response pattern. The
transformed payroll XML is returned to the SOAP caller. No separate
external payroll receiver is configured in this assignment.

## Source and target schemas

### Source: `Employee_Source.xsd`

Root element: `Employee`

  Source field    Type                Description
  --------------- ------------------- ---------------------
  `EmpID`         string              Employee identifier
  `FirstName`     string              First name
  `LastName`      string              Last name
  `BasicSalary`   decimal             Basic salary
  `HRA`           decimal, optional   Housing allowance
  `Allowance`     decimal, optional   Other allowance

`HRA` and `Allowance` are optional (`minOccurs="0"`).

### Target: `Payroll_Target.xsd`

Root element: `PayrollEmployee`

  Target field                       Type
  ---------------------------------- ---------
  `EmployeeNumber`                   string
  `FullName`                         string
  `SalaryDetails/Basic`              decimal
  `SalaryDetails/HousingAllowance`   decimal
  `SalaryDetails/OtherAllowance`     decimal
  `SalaryDetails/GrossSalary`        decimal

## Mapping logic

  ----------------------------------------------------------------------------------
  Source                  Function / logic        Target
  ----------------------- ----------------------- ----------------------------------
  `EmpID`                 Direct mapping          `EmployeeNumber`

  `FirstName`, `LastName` `Concatenate` with a    `FullName`
                          space                   

  `BasicSalary`           Direct mapping          `SalaryDetails/Basic`

  `HRA`                   `MapWithDefault`        `SalaryDetails/HousingAllowance`
                          (default `0`)           

  `Allowance`             `MapWithDefault`        `SalaryDetails/OtherAllowance`
                          (default `0`)           

  `BasicSalary`,          Two `Add` functions     `SalaryDetails/GrossSalary`
  defaulted HRA,                                  
  defaulted Allowance                             
  ----------------------------------------------------------------------------------

Calculation:

``` text
GrossSalary = BasicSalary + HRA + Allowance
```

The first `Add` calculates BasicSalary + HRA. The second `Add` adds
Allowance to that result.

## WSDL

WSDL file: `EmployeePayroll.wsdl`

The WSDL defines the employee request, payroll response,
`processEmployee` operation, SOAP binding, service, and port. It was
added as an iFlow resource and used for the SOAP sender configuration.

## Integration Flow configuration

  Setting                    Value
  -------------------------- ----------------------------
  Integration Flow ID        `IFLOW_EMPLOYEE_PAYROLL`
  Message Mapping artifact   `Employee_Payroll_Mapping`
  Sender adapter             SOAP
  SOAP endpoint path         `/employeePayroll`

## Testing

### Test 1 -- All salary fields provided

SOAP request body:

``` xml
<soap:Envelope
    xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:src="urn:employee:source">
    <soap:Header/>
    <soap:Body>
        <src:Employee>
            <src:EmpID>EMP1001</src:EmpID>
            <src:FirstName>Rahul</src:FirstName>
            <src:LastName>Sharma</src:LastName>
            <src:BasicSalary>30000</src:BasicSalary>
            <src:HRA>10000</src:HRA>
            <src:Allowance>5000</src:Allowance>
        </src:Employee>
    </soap:Body>
</soap:Envelope>
```

Expected calculation:

``` text
30000 + 10000 + 5000 = 45000
```

Successful SOAP response received:

``` xml
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
    <soap:Header/>
    <soap:Body>
        <PayrollEmployee>
            <EmployeeNumber>EMP1001</EmployeeNumber>
            <FullName>Rahul Sharma</FullName>
            <SalaryDetails>
                <Basic>30000</Basic>
                <HousingAllowance>10000</HousingAllowance>
                <OtherAllowance>5000</OtherAllowance>
                <GrossSalary>45000</GrossSalary>
            </SalaryDetails>
        </PayrollEmployee>
    </soap:Body>
</soap:Envelope>
```

**Result:** Successful. The deployed iFlow returned the expected payroll
values.

### Test 2 -- Optional fields missing

The mapping editor was also tested with this input, where `HRA` and
`Allowance` are omitted:

``` xml
<Employee>
    <EmpID>1002</EmpID>
    <FirstName>Mahesh</FirstName>
    <LastName>Kale</LastName>
    <BasicSalary>40000</BasicSalary>
</Employee>
```

Expected mapping result:

  Target field           Expected value
  -------------------- ----------------
  `EmployeeNumber`               `1002`
  `FullName`              `Mahesh Kale`
  `Basic`                       `40000`
  `HousingAllowance`                `0`
  `OtherAllowance`                  `0`
  `GrossSalary`                 `40000`

**Result:** The optional-field test worked in the Message Mapping
editor. An end-to-end Postman test with missing optional fields remains
an additional verification.
